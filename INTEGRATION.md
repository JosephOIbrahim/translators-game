# The Translators — CLAUDE.md Integration Guide

## Overview

The Translators generates **deterministic cognitive profiles** that can be integrated with Claude Code's Cognitive Substrate in your CLAUDE.md file.

**Key Properties:**
- Same 8 answers → Same profile → Same checksum (always)
- Profile includes semantic anchor for AI recognition
- Exports in multiple formats: Markdown, USDA, JSON-LD

---

## Quick Integration

### Option 1: Anchor-Based (Simplest)

Copy your profile's anchor into your CLAUDE.md or conversation:

```
[TRANSLATORS:101bfab5]
```

Claude will recognize this anchor and apply the associated communication preferences.

### Option 2: Markdown Integration

Add the exported markdown to your CLAUDE.md:

```markdown
## Communication Preferences

*Generated by The Translators — a cognitive interview*

| Dimension | Preference | Score | Behavior |
|-----------|------------|-------|----------|
| Pace | Quick | 0.20 | Get to the point — you process fast |
```

### Option 3: USD Substrate Integration

For full integration with the Cognitive Substrate, add the USDA export as a referenced prim:

```usda
def "TranslatorsProfile" (
    references = @/CognitiveSubstrate/Profile@
    doc = "Override profile from The Translators interview"
)
{
    # Pace
    custom string pace = "Quick"
    custom float pace:score = 0.20
    custom string pace:behavior = "Get to the point — you process fast"

    # Exploration
    custom string exploration = "Expansive"
    custom float exploration:score = 0.90
    custom string exploration:behavior = "You enjoy exploring tangents and connections"

    # ... additional traits
}
```

## How Determinism Works

### The Problem We Solved

Previously, profile generation had random elements:
- Garden metrics (seeds planted, flowers bloomed) were random
- Visual signature included non-deterministic counts
- AI behavior could vary based on aesthetic randomness

### The Solution

1. **Pure Functions**: `DeterministicProfileEngine` uses only pure functions
2. **Fixed Order**: Dimensions processed alphabetically
3. **Checksum Verification**: djb2 hash of serialized traits
4. **Separated Concerns**: Aesthetic garden ≠ Behavioral profile

```
Answers (deterministic) → Traits (pure computation) → Checksum (hash)
                                    ↓
                              Garden (can vary — aesthetic only)
```

### Verification

Run the determinism test:
```bash
node test-determinism.js
```

Expected output:
```
All tests: ✓ PASSED
Profile checksum: 101bfab5
```

## Signal Priority

When Claude encounters a Translators profile, it applies signals in fixed order:

1. **Emotional State** (highest priority)
   - `stuck`, `overwhelmed`, `frustrated` → ADHDCoach expert

2. **Mode Switch**
   - `switch to exploring` → Mycelium paradigm
   - `switch to focused` → Cortex paradigm

3. **Domain Expertise**
   - `usd`, `houdini`, `render` → VFX_Pipeline expert

4. **Task Type**
   - `implement`, `debug`, `plan` → Task-specific expert

5. **Profile Signals** (from Translators)
   - `pace:quick` → Lead with the answer
   - `exploration:expansive` → Follow tangents
   - etc.

## Checksum Format

Profile checksums follow this format:

```
TRL_v1|ambiguity:80|communication:20|exploration:90|...
       ↓
    djb2 hash
       ↓
    8-char hex (e.g., 101bfab5)
```

The `TRL_v1` prefix allows future version migration.
